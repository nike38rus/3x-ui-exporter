# v1.4.0

## Native TLS/mTLS & HTTP authentication, automated systemd installer, and multi-job Grafana dashboards

3x-ui-exporter **v1.4.0** introduces built-in HTTP server security (TLS, mTLS, Basic Auth, and Bearer Token authentication) for safe remote Prometheus scraping, an interactive `systemd` installer and lifecycle manager (`install.sh`), multi-job Grafana dashboard compatibility, and improved upstream diagnostics.

---

### Key Capabilities

#### Built-In HTTP Server Security (TLS, mTLS & Authentication)
- **Inbound TLS & mTLS:** Serve metrics over HTTPS (`--web.tls-cert-file`, `--web.tls-key-file` / `WEB_TLS_CERT_FILE`, `WEB_TLS_KEY_FILE`) with optional client certificate verification (`--web.tls-client-ca-file` / `WEB_TLS_CLIENT_CA_FILE`). Enforces TLS 1.2+ and modern AEAD cipher suites.
- **HTTP Basic & Bearer Authentication:** Protect `/metrics` using Basic Auth (`--web.basic-auth-username`, `--web.basic-auth-password`) or Bearer tokens (`--web.bearer-token`).
- **Secret file support:** Load credentials safely from disk via `--web.basic-auth-password-file` (`WEB_BASIC_AUTH_PASSWORD_FILE`) and `--web.bearer-token-file` (`WEB_BEARER_TOKEN_FILE`) without exposing secrets in process arguments.
- **Constant-time verification & identity protection:** Credentials are verified using SHA-256 + `subtle.ConstantTimeCompare`. Unauthenticated responses use a generic `realm="metrics"` header and neutral root page (`<h1>Metrics Exporter</h1>`) to prevent fingerprinting of 3x-ui or the exporter.
- **Optional `/healthz` protection:** Keep `/healthz` open for local liveness probes by default, or require authentication with `--web.auth-healthz` (`WEB_AUTH_HEALTHZ=true`).
- **Self-signed panel TLS support:** Added `--xui-insecure-skip-verify` (`XUI_INSECURE_SKIP_VERIFY=true`) for connecting to 3x-ui panels using self-signed HTTPS certificates.

#### Automated `systemd` Installer & Lifecycle Manager (`install.sh`)
- **One-command deployment & management:** Full lifecycle support via `install`, `update`, `status`, `config-tls`, and `uninstall` (`--purge`).
- **Hardened `systemd` service:** Runs unprivileged using `DynamicUser=yes` with strict filesystem and kernel sandboxing.
- **Native TLS & remote scraping setup (`config-tls`):** Configure server TLS certificates via systemd `LoadCredential` (allowing `DynamicUser` to read root-owned keys without changing permissions), auto-generate Bearer tokens, optionally lock down `/healthz`, and output a ready-to-paste `prometheus.yml` scrape snippet.
- **Automated 3-source self-test:** Installs, updates, and `status` checks automatically probe the running exporter and verify that all three upstream sources (`api`, `grpc`, and `expvars`) report `xui_exporter_scrape_success == 1`.

#### Upstream Diagnostics & Logging Refinements
- **Actionable HTTP error diagnostics:** Clear error messages for `401 Unauthorized` (check `XUI_API_TOKEN`), `403 Forbidden` (`Administrator` token scope required), and `3xx` redirects (reporting the target `Location` header when `XUI_URL` is missing a subpath or HTTPS scheme).
- **Dynamic slow-operation threshold:** `slow source operation` warnings now scale dynamically to `1/4` of `SCRAPE_TIMEOUT` (defaulting to `1s` when unset) instead of a fixed `100ms` threshold, eliminating false-positive warnings on high-latency clusters.

---

### Dashboard & CI Updates

- **Multi-job & custom scrape job support:** Removed the hardcoded `job="xui-exporter"` filter across all panels and template variables in both `grafana-3x-ui.v2.json` and `grafana-3x-ui.classic.json`, allowing custom Prometheus `job_name` configurations and multi-node scraping setups.
- **Rolling `edge` builds:** CI now publishes rolling pre-release `edge` binary archives to GitHub Releases on `main` branch updates and skips unnecessary container builds on documentation-only changes.
