# v0.6.0

## Concurrency and scrape latency optimizations

- Parallelize balancer queries in `readGRPC` using concurrent goroutines. Runtime balancer collection latency now scales to the delay of a single RPC rather than the sum of all configured balancers.
- Start expvars snapshot collection immediately in parallel with API requests at $t=0$ when an explicit `XRAY_METRICS_URL` is configured, reducing scrape time from $T_{api} + T_{expvars}$ to $\max(T_{api}, T_{expvars})$.
- Use atomic counters in test mocks to prevent race detector warnings under concurrent balancer collection.

## Optional exporter self-monitoring and client metrics

- Add optional `--include-exporter-metrics` flag and `INCLUDE_EXPORTER_METRICS` environment variable (default: `false`) to export Go runtime (`go_*`) and process (`process_*`) metrics for the exporter itself.
- Add optional `--collect-client-stats` flag and `COLLECT_CLIENT_STATS` environment variable (default: `false`) to export per-user/client traffic counters from Xray (`xui_client_traffic_bytes_total{client, direction}`).
- By default, both options remain disabled to preserve minimal memory footprint, zero overhead, and low metric cardinality.
