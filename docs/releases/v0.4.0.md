# v0.4.0

## Source contracts and metrics endpoint discovery

- Always emit success and duration series for api, grpc and expvars. A success value of 1 means requests succeeded and their responses satisfy the exporter contract; optional missing measurements are not errors.
- Always probe gRPC with ListOutbounds, even without balancers or panel configuration. Only query balancers whose configuration is known. Panel failures do not change successful gRPC status.
- Separate gRPC request/response failures from errors deriving balancer metrics using configuration.
- Discover the expvars HTTP endpoint from metrics.listen in current panel settings when XRAY_METRICS_URL is empty. Keep an explicit override for remote deployments and independent expvars collection during API failures.
- Resolve wildcard listeners to the matching loopback family. Do not cache endpoints, guess ports or fall back between discovered and explicit addresses.
- Update README with a source/request/metric map and the revised request budget.

Existing explicit XRAY_METRICS_URL settings continue to work. Deployment examples now use automatic discovery by default. Set an explicit URL for remote or port-mapped deployments.
