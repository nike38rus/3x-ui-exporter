# v1.7.1

## Decoupled scrape source collection and partial observatory data preservation

3x-ui-exporter **v1.7.1** is a patch release decoupling scrape collection across upstream data sources (`api`, `grpc`, `expvars`) to eliminate source cascading delays or timeouts, preserving partial Observatory probe observations during transient subcomponent errors, and clarifying sliding-window aggregation semantics in documentation.

---

### Bug Fixes & Refactoring

#### Exporter Core
- **Decoupled Source Collection:** Refactored collection across upstream sources (`api`, `grpc`, `expvars`) to execute fully independently and concurrently via dedicated result channels and synchronization signals. An API timeout or slow response now strictly isolates to `xui_exporter_scrape_success{source="api"} = 0` without blocking, delaying, or failing gRPC or Expvars metrics.
- **Partial Observatory Data Preservation:** Enhanced `ExpvarsSnapshot` with explicit observation presence tracking (`ObservationsPresent`), allowing valid Observatory probe states to feed into balancer operational health evaluation even if non-critical errors occur in other sections of the expvars response.
- **Contract & Fault Isolation Tests:** Added concurrent timeout isolation test `TestAPITimeoutDoesNotFailGRPC` using `testing/synctest` and expvars observation presence test `TestExpvarsObservationsPresent`.

#### Documentation & Dashboards
- **Quality Score Window Semantics:** Documented sliding-window gauge weighting nuances in `README.md` when computing outbound reliability ($R$) and probe success with `sum_over_time` over `$__range`.
- **Dashboard Refinements:** Cleaned up query comments and dashboard metadata across `grafana-3x-ui.classic.json` and `grafana-3x-ui.v2.json`.
